# Reliability (Milestone 5) — Tasks

*Implements `requirements.md` (REQ-REL-01 to REQ-REL-60) per `design.md`. Tasks in one wave touch different files and can run in parallel; where a task depends on another in the same wave, it says so. A wave starts only when the previous wave's checks pass. Prerequisites: Milestone 4 is done (HEAD `dd2e064`, 1502 tests in 55 files passing, typecheck clean, lint 0 errors and 1 known warning in `packages/mcp-catalog`, tree clean). This spec changes none of `lib/`, `data/`, `public/`, `app/globals.css`, or any existing component or page, and adds no `.github/workflows/ci.yml`, no `app/api/`, and no LLM code.*

*Owners (REQ-REL-54). **DP** = the `design-polish` agent (writes the four new files under `app/` only). **B** = the builder session or `gift-curator` (writes `package.json`, `vitest.config.ts`, `tests/**`, `docs/**`). **QA** = the read-only `qa-auditor` (writes under `docs/qa-reports/` only). A task that needs a change outside its owner's paths stops and reports it. A defect a new test finds in `lib/` is NOT fixed here: the task stops, logs the counterexample, and raises a spec change (no task in this milestone changes matching, safety, true-size, or conversation behaviour).*

*Before writing any `app/` file (Wave 1), re-read `node_modules/next/dist/docs/01-app/03-api-reference/03-file-conventions/error.md`, `loading.md`, and `not-found.md` (AGENTS.md: this Next.js version, 16.4.6, has breaking changes; `error.tsx` takes `retry`, not only `reset`). Before the coverage block (Wave 4), check the option names against the installed `@vitest/coverage-v8` 5.1.x. Record in the evidence log which props and options were used (REQ-REL-56).*

*Common checks, run at the end of every wave unless the wave says otherwise:* `npm test`, `npm run typecheck`, `npm run lint`, `npm run validate-catalog`. The 1502 existing tests stay green throughout (REQ-REL-53), including the three golden cases and every property test; the test count never falls. A failing test is fixed in the code under test or its generator. It is never loosened, skipped, or disabled (`tech.md`). A counterexample is logged with its fix (REQ-REL-37). Long commands run in the background with output in `/tmp/rel-*.log`; every `/tmp/rel-*` file, server, and pid is removed at the end of the task that made it (REQ-REL-58).

*No browser exists on this machine. Every browser, screen-reader, forced-colours, phone, second-device, and physical-calibration check stays "NOT RUN" in the QA note, and no task claims one (REQ-REL-57).*
